# Session — 2026-07-09 — Vev shoppable para VG: envolver el `vio-web-sdk` real

> Objetivo: una demo shoppable en Vev para un artículo de VG ("krise #3: Frizz og
> bruset hår") que funcione **exactamente como `vio-demo.vercel.app`** — mismo
> checkout, mismos métodos de pago. Tras varios intentos re-estilizando el código
> de Alan, pivoteamos a **envolver el `vio-web-sdk` real** en un proyecto Vev limpio
> (`vio-vev`). Arquitectura + gotchas documentados en
> [`architecture/vio-vev-integration.md §6`](../../architecture/vio-vev-integration.md).

## Arco de la sesión

1. **Pivote de enfoque.** `vev-vg-demo` (re-estilizar componentes de Alan) no daba
   paridad con el demo (checkout, pagos). Decisión: **wrap del SDK real**. Proyecto
   nuevo `~/Documents/GitHub/vio-vev` (paquete Vev `cq1lXld-TA9`), `node_modules`
   symlink al de Alan (trae react + `@vev/react` + `@vev/silke`). El SDK se bundlea a
   `vio-vev/vio-sdk/index.js` (esbuild de `vio-web-sdk/src/_vev-entry.ts`).

2. **Dos bloques y nada más.** *Vio Config (SDK)* (init + bootstrap + monta por portal
   toda la UI global: FAB + cart + checkout + product-detail) y *Vio Product (SDK)*
   (picker visual del catálogo). Defaults hardcodeados (host key + URLs + Stripe pk);
   **commerce key dinámica** vía bootstrap del sponsor.

3. **Batalla contra el entorno de build de Vev** (los gotchas caros — §6.2):
   - `vio-sdk/` **fuera de `src/`** (Vev transforma todo `src/` → rompe el bundle).
   - `Vio` = **singleton en `globalThis`** (Vev empaqueta cada componente con su propia
     copia del SDK → sin esto, carts/bootstrap separados → *"Sponsor 1 not found"*).
   - `Number(sponsorId)` en `commerceFor`/`findSponsor` (web-components pasan string).
   - guard de `registerVioElements` (build-eval sin `customElements`).
   - **un solo overlay** vía `globalThis.__VIO_OVERLAY_OWNER__` (evita N drawers).
   - **Product Card autosuficiente**: init-if-needed + reintento (montaje sin orden).
   - componentes en categoría **"Localhost"** → servidos en vivo por `vev start`;
     tras tocar el SDK: rebundle + `vev deploy` + reiniciar `vev start`.

4. **Pagos = como el demo (§6.4).** Apple Pay **cobra directo** desde el footer del
   carrito (dirección desde Wallet); Klarna abre el checkout en **modo express** (sin
   form de *Leveringsadresse*). El bug clave: el handler del wrapper ignoraba
   `e.detail.express` y abría el checkout **completo** (con dirección). Apple Pay
   confirmado en Safari tras **registrar el dominio** en Stripe. Vipps → checkout
   completo (no es express en el SDK).

5. **Pulido de UI (cambios en el SDK, rama `feat/vev-sdk-wrap`).**
   - Prop `hide-meta` en `<vio-product>` (modo solo-imagen).
   - Checkout **siempre panel lateral derecho** en desktop (antes full-width).
   - Botones **Vipps** (naranja de marca) + **Apple Pay** con logo Apple SVG + label,
     consistentes en carrito, detalle y checkout.
