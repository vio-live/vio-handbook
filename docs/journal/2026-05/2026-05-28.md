## Debugging de `api-commerce.vio.live` — Miguel

### Contexto General
El dominio **`api-commerce.vio.live`** enfrenta problemas de conectividad, devolviendo consistentemente **404 Not Found**. El análisis se realizó en comparación con **`api.reachu.io`**, que responde correctamente conectándose al mismo backend (`base-api`).

### Problemas Identificados
1. **Certificado TLS en proceso:**
   - El certificado de **api-commerce.vio.live** sigue en emisión bajo Cert-Manager con **Let's Encrypt**.
   - El redireccionamiento de tráfico al solver ACME está interfiriendo con el tráfico normal.

2. **Enrutamiento en Istio:**
   - Inicialmente, **`api-commerce.vio.live`** no estaba listado como host válido en el `VirtualService`. Esto se corrigió añadiéndolo.

3. **Restricciones en el backend:**
   - El servicio backend responde para **api.reachu.io**, pero las pruebas desde **api-commerce.vio.live** arrojan errores. Host headers y configuraciones de rutas específicas pueden estar relacionados.

### Acciones
1. **Cert-Manager:**
   - Se verificó el estado del certificado y la configuración temporal del Ingress.

2. **VirtualService:**
   - Se actualizó el `VirtualService` en Istio para soportar **api-commerce.vio.live** junto con **api.reachu.io**.

3. **Pruebas internas:**
   - Realizadas pruebas directas de conectividad interna desde pods:
     - Resultado: **404 Not Found** para tráfico hacia **api-commerce.vio.live**.
   - También se ajustaron headers en las solicitudes (sin éxito).

### Pendientes
1. Confirmar emisión del certificado TLS y eliminar redirección ACME.
2. Validar aceptación de tráfico multi-host en el backend.
3. Verificar configuración DNS (Cloudflare) para ambos dominios.
