# Sesión — 2026-05-19

## Objetivo

Confirmar que el autoscaler bajó nodos en QA tras la sesión de ayer y avanzar con la reducción de costos.

## Contexto

El autoscaler lleva activo desde la noche anterior pero los nodos seguían en 3. Se investigó por qué y se tomaron acciones correctivas.

## Hecho

### Diagnóstico
- QA seguía en 3 nodos porque cada nodo usaba ~70% de memoria (4GB de ~5.6GB aprovechable en D2s_v5)
- Total de memoria en uso: ~12GB — no cabe en 2 nodos D2s_v5 (11.2GB aprovechable)
- La causa: todos los deployments corrían con 2 réplicas y Redis con 4 réplicas

### Acciones ejecutadas

**1. Todos los deployments de QA bajados a 1 réplica:**
```bash
kubectl scale deployment/admin-panel deployment/api deployment/base-api \
  deployment/collections deployment/extensions deployment/graph-ql \
  deployment/middleware deployment/orders deployment/payment-processors \
  deployment/products deployment/shopcart deployment/shopify-export \
  deployment/shopify-import deployment/socket-server deployment/tracking \
  deployment/users deployment/webapp --replicas=1 -n default
```

**2. Redis y Redis Sentinel bajados a 1 réplica:**
```bash
kubectl scale statefulset/redis statefulset/redis-sentinel --replicas=1 -n default
```

**3. Integraciones de terceros apagadas (réplicas=0) — no se usan activamente en QA:**
```bash
kubectl scale deployment/bigcommerce-app deployment/shopify-export \
  deployment/shopify-import --replicas=0 -n default
```

> ⚠️ `bigcommerce-app`, `shopify-export`, `shopify-import` están en 0 réplicas en QA.
> Levantar si se necesita testear flujos de BigCommerce o Shopify: `kubectl scale deployment/<nombre> --replicas=1 -n default`
