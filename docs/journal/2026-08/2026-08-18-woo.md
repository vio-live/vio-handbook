## Review ronda 1 — los 2 fixes (`5c12108`)

### 1. Escape late (todo lo echo'd escapado)
El equipo NO acepta `phpcs:ignore` para output: hay que escapar en el punto de salida ("escape
late"), incluso markup hardcodeado. Los íconos SVG inline de `Config_Page::icon()` estaban con
`phpcs:ignore EscapeOutput`. Fix:
- Constante `Config_Page::SVG_KSES` (allowlist de tags/atributos SVG: `svg/path/line/polyline/
  circle/rect/g` + `viewBox`, `d`, `stroke*`, etc.).
- Cada `self::icon('x')` al echo → `wp_kses( self::icon('x'), self::SVG_KSES )` (15 sitios).
- Logo (`$brand`), contador (`$count_html`) y valores de `kv()` (`$value_html`) →
  `wp_kses_post()`.
- **Nota clave:** `wp_kses` pasa `viewBox`→`viewbox`, PERO el parser HTML de los browsers lo
  corrige en SVG inline (foreign-content adjustment), así que los íconos escalan bien.
  Verificado — no rompe.

### 2. Prefijo único ≥5 chars
`vio` (3) es demasiado corto (piden >4). El tool de review parte en el primer `_`, así que el
primer token tiene que ser ≥5 → **`viosync`**:
- Defines `VIO_WC_SYNC_*` → `VIOSYNC_*`; namespace `Vio\WooSync` → `VioSync`; acciones
  `wp_ajax_vio_*` → `viosync_*`; opciones `vio_apikey/currency/environment` → `viosync_*`;
  filtro `vio_wc_sync_api_base` → `viosync_api_base`; transient `vio_updating_` →
  `viosync_updating_`; nonce `vio_sync` → `viosync_sync`; menu slug `vio` → `viosync`; handles
  `vio-wc-sync-*` → `viosync-*`; objetos JS `vioConfig`/`vioWcSync` → `viosyncConfig`/
  `viosyncData` (+ los callers en `config.js`/`products.js`).
- **Se MANTUVO** el post-meta `vio-*` (`vio-product-id` lo escribe el backend de Alan =
  contrato externo; los demás por consistencia) y las **clases CSS `vio-*`** (no son
  identificadores globales). Se le aclaró al reviewer en la respuesta.
- ⚠️ **Gotcha:** `col_vio_sync` (COLUMN key de la list-table) está atado a la clase CSS
  `.column-col_vio_sync` en `admin.css` → hay que renombrar en PHP **y** CSS juntos.
- ⚠️ **Rename hecho con `perl -pi` via `find -exec`.** El `sed` con comillas mezcladas falló, y
  el shell es **zsh** → `$VAR` sin comillas NO hace word-split (lo pasa como un solo arg). Con
  `find -exec perl -pi -e '...' {} +` quedó limpio.

## Nuevas versiones (flujo, documentado en el playbook §5)

Cambiar código → subir `Version` (header) + `Stable tag` (readme) + `VIOSYNC_VERSION` (deben
coincidir) → changelog en readme → Plugin Check 0/0 → commit → `git tag x.y.z &&
git push origin x.y.z` → la Action deploya. `Stable tag` define qué versión bajan los usuarios;
la versión siempre tiene que subir; los assets se refrescan en cada deploy.
