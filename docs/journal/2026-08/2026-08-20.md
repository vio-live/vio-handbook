## Qué se construyó (todo verificado, no solo escrito)

1. **Contrato v1 congelado** — Zod en
   `vio-analytics/src/contract/analytics-schema.ts` + `docs/EVENTS_CONTRACT.md`
   (referencia canónica para las re-declaraciones Swift/Kotlin). Review
   adversarial incorporado: dedupe por `event_id` estable
   (ReplacingMergeTree/`$insert_id`), ventana de clock-skew [-30d,+1h],
   caps de cardinalidad, `props` ≤8KB no indexado, nombres server-only
   inforjables por clientes, tenant SIEMPRE resuelto server-side.
2. **F1 — repo [`vio-live/vio-analytics`](https://github.com/vio-live/vio-analytics)**
   (main): `POST /v1/events` (batch ≤500, validación por-evento, 202 rápido),
   auth api-key contra `client_apps` con cache TTL, path interno con token para
   el outbox, CORS + `text/plain` (sendBeacon sin preflight), writer ClickHouse
   batcheado con buffer acotado, sink Mixpanel (EU default), 37 tests Vitest,
   Dockerfile, compose (ClickHouse local), CI + deploy workflows, Terraform
   (3 Container Apps + OIDC + roles, `ignore_changes` en imagen).
3. **F4 — [vio-backend#43](https://github.com/tipiodevelopment/vio-backend/pull/43)**:
   `ad_activation` y `cart_intent` espejados vía outbox transaccional
   (`server/events/analytics-mirror.ts`); el worker ramifica por
   `module:'analytics'` ANTES del switch de scope (nunca WS). Config-gated.
4. **F2 — [vio-web-sdk#18](https://github.com/vio-live/vio-web-sdk/pull/18)**:
   `Vio.analytics` (cola pre-init, anon/session ids, batch+beacon, auto-funnel
   de comercio con snapshot pre-clear para Apple Pay, `observeImpression`,
   sinks colector/dataLayer/DOM, SSR-safe, `start()` explícito).
