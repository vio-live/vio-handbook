## Nextra nav / sidebar customization (the tricky part)

Goal: **Commerce is its own header section with an isolated sidebar (only its own pages), and
the existing SDK nav stays exactly as it was.**

- **Header:** `commerce` is `type: 'page'` **without `href`** in `content/_meta.js`, placed
  before `about`. (A `type:page` WITH `href` is a plain link and does NOT scope the sidebar.)
- **❌ First attempt (reverted):** I also made `swift`/`kotlin` `type:page`. That isolated
  Commerce but turned the SDKs into navbar tabs and made `/swift`→404 (folders with no
  `index`). The user rejected it — **do not restructure the SDK nav.**
- **✅ The fix (customization):** keep `swift`/`kotlin` as root sidebar folders, and add a CSS
  rule in `app/vio-theme.css` that hides the SDK/Index items **only on `/commerce` routes**:
  ```css
  .nextra-sidebar:has(a[href^="/commerce"]) li:has(a[href="/"]),
  .nextra-sidebar:has(a[href^="/commerce"]) li:has(a[href^="/swift"]),
  .nextra-sidebar:has(a[href^="/commerce"]) li:has(a[href^="/kotlin"]) { display: none !important; }
  ```
  Route detection works because the `/commerce` links only render in the sidebar **inside** the
  Commerce section (Commerce is `type:page`, so it doesn't bleed into the SDK sidebars).
- **Steps as left-sidebar sub-items:** `toc.float: false` in `app/layout.jsx` moves each page's
  headings into the left sidebar (nested under the active page). This is **site-wide** — a
  per-page override 500s (per-page `theme.toc` only accepts a boolean). The user accepted the
  SDK docs getting the same treatment.
- **Brand icons** (white) via `_meta.jsx` (title as a JSX element using `react-icons` `SiWoo` /
  `SiShopify`) and on the integration cards (`<Cards.Card icon={...}>`). WooCommerce uses
  **`SiWoo`** (the new "Woo" brand), not `SiWoocommerce`. Note: `_meta` must be `.jsx` (not
  `.js`) to hold JSX titles.
