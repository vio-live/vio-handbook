# Session — 2026-06-09 — WooCommerce → Vio sync: connect flow, sync investigation & handoff

> Continuation of [`2026-06-09 — woo`](./2026-06-09-woo.md) (which bootstrapped the area and
> rewrote the plugin). This session got the plugin **talking to the backend end-to-end**,
> found the one thing that blocks a full sync, cleaned up delete/unsync, and **merged
> everything to `main`**. Canonical reference (kept current):
> [`architecture/woocommerce-sync`](../../architecture/woocommerce-sync.md).

## Goal

Take the rewritten plugin from "loads and is correct" to "**actually connects and syncs**":
load currencies, connect the store (REST key + webhooks), watch a real product sync, and fix
whatever's wrong with the flows (sync status, delete/unsync). Then consolidate to `main` and
document for handoff.

## Done

1. **Currency list fixed.** Empty dropdown was because **prod `api.reachu.io` was down**
   (HTTP 000). Pointed the dev store at **staging `api-qa.reachu.io`** → currencies load.
2. **HTTPS via a Cloudflare named tunnel.** OAuth callback + webhooks need a public HTTPS
   origin. Quick/trycloudflare tunnels 404'd from this env (no edge propagation); a **named
   tunnel** now maps **`https://woo-dev.vio.live` → `localhost:8888`** (verified **200**).
   Two dev `mu-plugins` make WP behave behind it: `zzz-tunnel-proxy.php` (honor
   `X-Forwarded-Proto`) + `zzz-dev-memory.php` (memory). Config in
   `~/.cloudflared/config-woo-dev-local.yml`.
3. **Connect store works end-to-end.** OAuth creates **1 REST API key** (`Vio WooCommerce Sync`)
   + **2 order webhooks**. Hardened detection: the store is "connected" if a webhook matches a
   managed name **or** its delivery-URL host == the backend host — so it's robust to the backend
   naming the hooks **"Outshifter order.*"** and to the Reachu→Vio host flip. Connected state now
   shows a green success notice + Disconnect, and hides the fields.
4. **Investigated why products stay "Syncing".** Traced the model: **Vio Sync → `create-sqs`
   (returns `messageId` → meta `vio-sqs-id`) → "Sent"** → backend should **write `product-id`
   back** → column flips to Synced. Confirmed with the user the **backend does create the
   products**, but the `product-id` never returns. Probed **~12 endpoints**: the API has **no
   filter** by `originId`/`sku`/`search` (`GET /api/products` returns the full ~9,353 catalog),
   so the plugin **cannot poll** for it. → **backend write-back is required** (see Handoff).
5. **Sync column** "Syncing…" (endless) → **"Sent"** with a tooltip explaining it's queued.
6. **Delete / unsync refactored** into one coherent path (`Sync::delete_by_post(… bool
   $deleteRemote)`): always clears local meta (so "Sent"-only products can be unlinked), deletes
   remote only when the id is known; "Delete from Vio" batch-deletes known ids; **trash keeps
   images** (restorable); **permanent delete** unlinks + drops Vio-owned images.
7. **Consolidated to `main`** in both repos and **moved both to the `vio-live` org**. Plugin
   `main` @ `a3c01c6`; dev-env `main` @ `b8bb02b` (scaffold header → English, author/URLs → Vio).

## The blocker (one thing) → handoff to Alan / backend

Products queue fine but the column is stuck on **"Sent"** because the **backend never writes the
Vio `product-id` back** into the store. Everything keyed on the remote id (auto-update on save,
true remote delete) can't act until it does. The plugin **can't** work around it — no filter
endpoint exists. Backend needs to either:

- **write `product-id` back** to the store (meta `vio-product-id`) via the REST API after
  creating the product, **or**
- **expose a filter** like `GET /api/products?origin=WOOCOMMERCE&originId={postId}`.
- (cosmetic) rename the backend's **"Outshifter"** webhooks to **"Vio"**.

Full detail: [`architecture/woocommerce-sync` § The blocker](../../architecture/woocommerce-sync.md#-the-blocker-the-product-id-never-comes-back).
**The user is handing the backend side to Alan.**

## Decisions

- **Detect connection by delivery-URL host, not webhook name** — robust to the "Outshifter"
  naming the backend applies and to the eventual Reachu→Vio host change.
- **`delete_by_post()` always unlinks locally** even with no remote id — otherwise "Sent"-only
  products are un-deletable from the UI while the `product-id` blocker stands.
- **Run the dev store against staging** for now, since prod was down.
- **Merge straight to `main`** (fast-forward, no AI attribution) at the user's request — the
  feature branch `feature/sync-flow` was deleted after merging.
