# Session — 2026-06-22 — Woo→Vio: migración de endpoints a vio.live + currency required

> Continuación del [2026-06-12](./2026-06-12-woo.md) (que cerró el blocker del
> product-id). Alan terminó sus cambios de backend (migración al ambiente nuevo
> de Vio Commerce); este review los trajo, los probó y dejó el plugin apuntando a
> los hosts nuevos. Plugin `vio-woocommerce-sync` @ **`098cf94`**.

## TL;DR

- **Migración de endpoints a vio.live.** El backend pasó de Reachu
  (`api.reachu.io` / `api-qa.reachu.io`, ahora **caídos**) al ambiente nuevo de
  Vio Commerce: **prod `api-ecom.vio.live`**, **staging
  `api-ecom-staging.vio.live`**. El plugin ya era env-agnostic → solo se
  actualizaron los 2 defaults de `Api_Client::ENVIRONMENTS` (+ docs).
- **La "activación" (`vioActive:false`) NO era un blocker** — es by-design: los
  productos se activan al **publicarlos** en Commerce (flujo interno), no por el
  sync. Cerrado.
- **Currency obligatoria al conectar** (pedido de Angelo): JS + guard backend.
- **Test:** 6 productos con imágenes reales para probar el sync de imágenes.
- **Abierto (backend/Alan):** `/api/currencies` **flaky** — `000` / `417
  "Connection lost"` intermitente — inestabilidad de DB del cluster nuevo.

(06-18). Para la **base-api** (lo que usa el plugin WooCommerce):

| | URL | Nota |
|---|---|---|
| **prod** | `api-ecom.vio.live` | cluster `rg-vio-commerce-prod` |

`-dev` es un namespace de desarrollo aparte (por eso tenía el `/api/currencies`
roto). Reachu viejo (`api.reachu.io` / `api-qa.reachu.io`) **caído**.

## Activación — cerrada como by-design

`vioActive` se prende al **publicar** los productos en Commerce (interno), no en
el sync. Que nazcan `active=false` es esperado. No es del plugin ni un blocker.
(Esto reemplaza el "2º blocker" que el journal del 06-12 dejó abierto.)

## El connect que fallaba — diagnóstico

1. Primero pareció **"key no provisionada" (401)** — fue **error de diagnóstico
   mío**: probé la key contra **prod** mientras la cuenta de Angelo está en
   **staging**. Contra staging la key **sí** autentica. (Lección: probar la key
   contra el host correcto.)
2. El problema real es **`/api/currencies` flaky** — intermitente `000` / `417
   "Connection lost"` (la conexión a la DB se corta a mitad de query). Backend /
   Alan (`fix typeorm` / `config ssl bd` en curso). El plugin tolera el error
   (dropdown de moneda vacío), pero la fuente es inestable.

## Discrepancia de URL de staging — resuelta

Alan (`8f61388`) puso staging = `api-ecom-dev.vio.live`; el host real/sano es
**`api-ecom-staging.vio.live`** (Angelo lo confirmó; coincide con

**alinearon los 2 docs** del plugin (`backend-integration.md`, `CODE-AUDIT.md`)
que decían `-dev`. Cero refs a `-dev` en el repo.
