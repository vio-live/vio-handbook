## Two build bugs caught by the pre-publish validation 🎯

Both invisible to `npm run build` / `npm pack`; only a real browser consuming the package showed them.
Full writeup: [`lessons/web-sdk-tsup-singleton-and-build`](../../lessons/web-sdk-tsup-singleton-and-build.md).

1. **`splitting:false` duplicated the `Vio` singleton** across the `index` and `ui` entries →
   `Vio.init()` configured one instance, the components used another → 0 products.
2. **`splitting:true` + partial `sideEffects`** → the custom-element registration lived in shared
   chunks not covered by `sideEffects` → tree-shaken → components never `define`d.

Fix: **`splitting:true` + `sideEffects:["./dist/**"]`**.

## Decisions

- **Published public under the `@vio-live` npm org** (the plain `vio-live` org name was taken; angelo
  converted a `vio-live` account into the org). Name `@vio-live/web-sdk`. MIT, copyright "Vio" (not Reachu).
- **The demo consumes the published package, not a local source alias** — keeps the live sales demo
  **stable and decoupled** from in-flight SDK work. Going forward: improve the SDK locally → publish a
  new version → bump the demo deliberately (never automatic).
- **Pushed only the SDK; left the demo repo as-is** — it's a sales tool; don't churn it.
- **Klarna payment proxy stays on socket-server for now**, flagged to move to `vio-commerce` (tech debt).
