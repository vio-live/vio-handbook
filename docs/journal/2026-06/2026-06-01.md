## 3. Bugs encontrados y corregidos

### Bug 1 — `drizzle.config.ts` faltaba en imagen Docker
**Síntoma**: Container App crasheaba con `F /app/drizzle.config.json file does not exist`  
**Causa**: El Dockerfile no copiaba `drizzle.config.ts` ni `shared/` al stage de producción  
**Fix** (`Dockerfile`):
```dockerfile
COPY --from=builder /app/drizzle.config.ts ./
COPY --from=builder /app/shared ./shared
```

### Bug 2 — Contraseña PostgreSQL con caracteres especiales rompe DATABASE_URL
**Síntoma**: `ERR_INVALID_URL` — contraseña contenía `+`, `#`, `$` sin encodear  
**Causa**: `random_password.pg_admin` usa `override_special = "!#$%&*-_=+"`, los caracteres especiales no estaban URL-encodeados  
**Fix permanente** (`vio-infra-tf/modules/socket-server-env/main.tf`):
```hcl
database_url = "postgresql://pgadmin:${urlencode(random_password.pg_admin.result)}@..."
```
**Fix inmediato**: secreto del Container App actualizado directamente via `az containerapp secret set`

### Bug 3 — OIDC sin credencial federada para entorno `production`
**Síntoma**: `AADSTS700213: No matching federated identity record found for subject 'repo:...:environment:production'`  
**Causa**: El deploy.yml usa `environment: production` en el job cuando el input es production, cambiando el subject del OIDC  
**Fix**: Añadida credencial federada en app `socket-server-cicd` (`9c9aa12a-f97b-415f-805f-007336318fcc`):
```
subject: repo:tipiodevelopment/socket-server:environment:production
```

## 4. Restore de data local → producción

Flujo implementado para restaurar snapshots en PostgreSQL privado (VNet):

1. `yarn db:snapshot:push` — sube dump local al Blob
2. Container App Job `db-restore-job` (en `rg-socket-server-production`) descarga el snapshot via SAS URL y ejecuta psql dentro de la VNet

Job ejecutado exitosamente — data de angelo en prod.

**Nota**: El Container App Job `db-restore-job` existe en `rg-socket-server-production`. Reutilizar para futuros restores actualizando el `BLOB_URL` con un nuevo SAS.
