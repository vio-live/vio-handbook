# Session — 2026-06-09 — WooCommerce → Vio sync plugin (new area)

> Third distinct session of the day, separate from the [Kotlin/TV review](./2026-06-09.md)
> and the [Web SDK publish](./2026-06-09-web-sdk.md). This one **bootstraps a brand-new area**:
> a WooCommerce plugin that syncs products into Vio. Canonical reference (declares the area):
> [`architecture/woocommerce-sync`](../../architecture/woocommerce-sync.md).

## Goal

Stand up a WooCommerce dev environment, then **rewrite the legacy `Reachu Export` plugin as
`Vio WooCommerce Sync`** — same functionality, Vio branding, prod/staging support, and
WordPress/WooCommerce best practices.

## Done

1. **Dev environment** → repo **`angelosv/woo-vio`** (private): `@wordpress/env` (WordPress +
   WooCommerce in Docker). Hit a real blocker — **`wp-env start` only brings up MySQL and aborts**
   on Docker 29.x — so the start/setup flow was rebuilt on `docker compose` directly
   (`bin/bootstrap.sh` idempotent setup + `bin/dev.sh` day-to-day). Site at `localhost:8888`.
2. **Audit of the legacy plugin** (`~/Downloads/outshifter-export`, "Reachu Export v3.8") →
   `woo-vio/docs/audit-reachu-to-vio.md`. Findings: ~217 `reachu` refs, opaque `OSEWCPHJC_`
   prefix, 9 API endpoints, **5.9 MB `vendor/` that is statically dead** (0 imports), and 5
   security holes (`wp_ajax_nopriv` everywhere, no capability checks, missing nonces, unescaped
   output, raw SQL).
3. **Full modular rewrite** → repo **`angelosv/vio-woocommerce-sync`** (private, going public).
   1196-line monolith → 8 classes under namespace `Vio\WooSync` (bootstrap + `includes/`).
   Vio naming (`VIO_WC_SYNC_*`, `vio_*`, `vio-*`), security hardened, HPOS declared, i18n, no
   `vendor/`. Verified: `php -l` clean on all files + activates in `woo-vio` with no fatals.
4. **Prod/staging environments made dynamic** — `Api_Client` points at Reachu today
   (`production → api.reachu.io`, `staging → api-qa.reachu.io`) but resolves in cascade
   (per-env `wp-config` constant → map → filter), so the flip to `api-commerce.vio.live` is a
   one-liner / zero-code. Verified live via `wp eval`.
5. **Both repos pushed** to GitHub (private).
6. **Scrubbed AI attribution** from `vio-woocommerce-sync` history (rewrite + force-push) before
   it goes public — see Decisions.

## Decisions

(Full rationale in [`architecture/woocommerce-sync` § Decisions](../../architecture/woocommerce-sync.md#decisions).)

- **Rewrite, don't patch** the monolith; **plugin and dev-env are separate repos**.
- **Dropped the 5.9 MB `vendor/`** (dead code).
- **URLs dynamic, Reachu today**, Vio-ready with zero code change.
- **No AI attribution in commits** — this is **LOCKED rule #6**
  ([`onboarding/agents`](../../onboarding/agents.md)). I had wrongly added `Co-Authored-By`
  trailers earlier in the session; rewrote `vio-woocommerce-sync` history to remove them. The
  handbook *does* trace agent work — but in **frontmatter** (`participants: [angelo, claude]`),
  never in git.
