## Detalles relevantes por tarea

### T1 — Patrón a seguir
`vio-infra-tf` ya tiene el módulo `socket-server-env` que es el reference para el patrón modular (`locals {}` source of truth + módulo por entorno). T1 debe replicar ese estándar para vio-commerce.

**IPs estáticas obligatorias:** se crean con `azurerm_public_ip` con `allocation_method = "Static"`, NO como `data` resources. La regla anti-drift es que si el cluster se recrea, las IPs sobreviven y el DNS no se rompe. Ver `azure-overview.md` sección "IPs estáticas (permanentes)" para los precedentes en `reachu-prod` y `kubernetesqa`.
